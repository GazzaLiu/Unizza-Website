## Problem Statement

Unizza 是一個想接遊戲外包案（B2B）的遊戲團隊，目前**還沒有接過案子**。已有兩款自家作品（Muffin Time 吸爆鬆餅、Sky Team 天合小隊）、一個從 Webflow 匯出的網站雛型（`webflow-site/index.html`、`contact.html`），以及網域 `unizzagames.com`。目標是用 $0/月 的方式把官網放上線。

真正的問題不是「怎麼部署」，而是：**官網是 Unizza 用來說服第一個客戶的工具**。它必須讓被主動送上連結的遊戲公司／發行商，在 30 秒內相信 Unizza 做得出遊戲，並能直接聯絡到人。

## Demand Evidence

尚無。沒有客戶、沒有詢問、沒有具名的潛在客戶。本設計不假設官網會自己帶來需求；需求驗證由 The Assignment 負責。

## Status Quo

- 沒有任何對外可發送的網址。
- 雛型是 Webflow 模板改到一半：仍有「Velocity」「Heading」「Grow Your Business.」「Our Most Popular services」等模板字；`contact.html` 有一個定位在舊金山的 Google 地圖 widget（`w-widget-map`，latlng 37.77,-122.41）。
- 雛型技術上**仍依賴 Webflow**：`index.html` 的圖片、CSS、JS 幾乎全部引用 Webflow 的 CDN（`cdn.prod.website-files.com`、`d3e54v103j8qbb.cloudfront.net`），repo 裡的 `webflow-site/assets/` 本地副本 `index.html` 完全沒用到。`contact.html` 混用兩種 runtime：CDN 版 `webflow.schunk.d97efad…` 與本地版 `webflow.schunk.b4435221…`、`webflow.307d5e96…`。
- 聯絡表單（`contact.html` `#email-form`）是 Webflow 表單：`method="get"`、無 `action`、欄位名為 `Name` / `Email` / `field-2`（訊息欄沒有 `required`），Turnstile sitekey 屬於 Webflow。Webflow 官方說明匯出的程式碼中表單停用，部署到哪裡都送不出去。頁面上顯示 `info@unizzagames.com`。
- **網域現況（2026-09-29 以 DNS 查詢確認）：** nameserver 為 `dns1/dns2.registrar-servers.com`（Namecheap），MX 為 `smtp.google.com` —— `unizzagames.com` 的信箱目前由 Google Workspace 收信。

## Target User & Narrowest Wedge

- **目標使用者（類別）：** 遊戲公司或發行商中負責找外包的人（製作人、外包經理），需求為外包開發、移植或美術。
- **尚缺：** 具體的人名。使用者在本次 session 選了類別而非人名，這是最大的缺口，交由 The Assignment 補上。
- **最窄切入點：** 兩頁的網站 —— 首頁（兩款已上架作品當證據 + 能做什麼 + 團隊）＋ 一個真的會寄到信箱的聯絡表單。不做部落格、不做 SEO、不做多語系（除非 Open Question 1 另有結論）。

## Premises

使用者於本次 session 同意（第 3 條依審查意見精確化）：

1. 官網的任務是讓「被主動送連結的遊戲公司／發行商」30 秒內相信 Unizza 做得出遊戲，而不是靠 SEO 招攬陌生人。
2. 模板殘留內容必須在對外發送連結前清掉。技術上可以先上線，但網址要等內容改完才發出去。
3. 網站必須完全脫離 Webflow：**對 Webflow 擁有的主機（`*.website-files.com`、`d3e54v103j8qbb.cloudfront.net`）請求數為 0**，所有 Webflow 產出的圖片、CSS、JS 存在 repo 裡。允許的第三方來源僅限：Google Fonts（`ajax.googleapis.com` 的 webfont.js、`fonts.googleapis.com`、`fonts.gstatic.com`）與 Turnstile（`challenges.cloudflare.com`）。
4. 聯絡表單上線時就要能真的寄到信箱，並有防垃圾信機制。
5. 成本 $0/月；託管在 Cloudflare。

## Approaches Considered

- **A) Cloudflare Pages + Pages Function** —— 使用者原本的計畫。可行，但 Cloudflare 目前的官方指引是新專案使用 Workers，Pages 僅維護。工作量與 B 相同，因此未選。
- **B) Cloudflare Workers 靜態資源 + 同一個 Worker 處理表單** —— **已選。**
- **C) Astro 重建** —— 在沒有第一個客戶前花一週重寫是優先順序錯誤。觸發條件：接到第一個案子，或作品超過 4 件、手改 HTML 開始痛苦時。

## Recommended Approach

**B：Cloudflare Workers 靜態資源。** 與 A 同樣 $0、同樣工作量；設定檔（`wrangler.jsonc`）在 repo 裡可重現；符合 Cloudflare 目前對新專案的指引。

### 1. 專案結構與 Worker 設定

```
Unizza-Website/
├── public/                 # 由 webflow-site/ 改名而來，靜態資源根目錄
│   ├── index.html
│   ├── contact.html
│   ├── 404.html            # 簡單的找不到頁面，沿用網站 CSS
│   ├── _headers
│   └── assets/...          # 所有 Webflow 產出的圖片、CSS、JS
├── src/worker.js           # 只處理 /api/*，其餘由靜態資源處理
├── wrangler.jsonc
├── .dev.vars               # 本機用的 Turnstile 測試 secret（加入 .gitignore）
└── docs/designs/cloudflare-launch.md
```

`wrangler.jsonc`：
- `main: "src/worker.js"`，`compatibility_date` 設為實作當天。
- `assets: { directory: "./public", run_worker_first: ["/api/*"], html_handling: "auto-trailing-slash", not_found_handling: "404-page" }`。在 `auto-trailing-slash` 下 `/contact.html` 會轉到 `/contact`，因此站內連結一律改為無副檔名（`/`、`/contact`）。
- `workers_dev: false`、`preview_urls: false`（不公開 `*.workers.dev` 網址與預覽網址，避免重複內容被索引；預覽改用本機 `wrangler dev`）。
- `routes`：以 Custom Domain 綁定 `unizzagames.com` 與 `www.unizzagames.com`。
- `vars`：`CONTACT_TO = "gazzaliu@unizzagames.com"`、`ALLOWED_HOSTNAMES = "unizzagames.com,www.unizzagames.com"`。`DRY_RUN` **不得**出現在 `wrangler.jsonc`，只存在 `.dev.vars`。

Worker 路由：`POST /api/contact` → 表單處理；`/api/contact` 的其他方法 → 405；其他 `/api/*` → 404。

### 2. 脫離 Webflow（資產在地化）

- 將兩頁所有 Webflow CDN 網址改寫為 `/assets/...` 本地路徑；本地沒有的檔案從原網址下載補進 `public/assets/`。
- **每頁只保留一套一致的 Webflow runtime：** 以 `index.html`（全 CDN 引用、未混用）的 runtime 檔案組為準，下載其全部檔案到本地；`contact.html` 刪除重複的 `webflow.schunk.*` script 標籤，改用同一組。
- Webflow runtime 會在執行期動態載入 `webflow.achunk.*.js`（不在 HTML 裡）。以瀏覽器開啟本地站、點過所有互動，把 Network 面板出現的 Webflow 請求全部下載補齊。
- 移除 jQuery 網址上的 `?site=` 參數。保留 `<html>` 上的 `data-wf-page` / `data-wf-site`（IX2 互動動畫需要）。
- 移除 `contact.html` 的 Google 地圖 widget（`w-widget-map`）。Unizza 無需公開地址；若日後需要，改為一行文字地址。
- **驗收：** 兩頁的 Network 面板中，Premise 3 允許清單以外的外部請求為 0；Console 無錯誤；首頁淡入等互動動畫仍運作。

### 3. 聯絡表單

**前端（`contact.html`）**
- 表單欄位：`name`（`required`，`maxlength=256`）、`email`（`type=email`，`required`，`maxlength=256`）、`message`（textarea，**新增** `required`，`maxlength=5000`）。
- 送出方式：移除表單上的 `data-wf-page-id`、`data-wf-element-id`、`data-turnstile-sitekey`；以 **capture 階段** 的 `submit` 監聽器呼叫 `preventDefault()` 與 `stopImmediatePropagation()`，阻止 Webflow 的表單處理，再用 `fetch('/api/contact', { method: 'POST', body: JSON })` 送出：
  `{ name, email, message, turnstileToken }`
- Turnstile 以**明確渲染**載入（`challenges.cloudflare.com/turnstile/v0/api.js?render=explicit`），由 `turnstile.render('#turnstile', { sitekey, callback, 'expired-callback' })` 建立。sitekey 依 `location.hostname` 選擇：`localhost` / `127.0.0.1` 用 Cloudflare 測試 sitekey `1x00000000000000000000AA`，其他一律用 Unizza 的正式 sitekey（sitekey 是公開值，可寫在 HTML/JS）。因為正式網域不可能是 localhost，正式環境不會用到測試 key。Webflow 的 sitekey 移除。
- `turnstileToken` 取自 `callback(token)` 的參數。**送出按鈕預設 disabled**，callback 觸發後才啟用；`expired-callback` 觸發時清空 token 並再次 disabled。
- 送出期間按鈕 disabled。依回應顯示：
  - **200：** 隱藏表單，顯示既有的 `.w-form-done` 區塊。
  - **400：** 回應 body 為 `{"error":"invalid","field":"name"|"email"|"message"|null}`；有 `field` 時在該欄旁顯示「請檢查此欄」，`field` 為 null（JSON 解析失敗）時顯示通用訊息。
  - **403：** 顯示「驗證失敗，請再試一次」。
  - **5xx / 網路錯誤：** 顯示 `.w-form-fail`，內含「或直接寄信到 info@unizzagames.com」的 mailto 連結。
  - 任何非 200：清空已存的 token、呼叫 `turnstile.reset()`（token 只能用一次），按鈕**維持 disabled**，只由下一次 `callback` 重新啟用。
- Turnstile 本身失敗時（`error-callback` 觸發，或 `api.js` 載入後 10 秒內 `window.turnstile` 仍不存在，例如被廣告阻擋器擋掉）：顯示 `.w-form-fail`，內含「驗證元件無法載入，請直接寄信到 info@unizzagames.com」的 mailto 連結，確保潛在客戶一定聯絡得到人。

**Worker（`POST /api/contact`）**
1. 解析 JSON；失敗回 400 `{"error":"invalid","field":null}`。
2. 驗證：`name`、`email`、`message` 必填，長度上限 256 / 256 / 5000；`email` 須符合 `^[^\s@]+@[^\s@]+\.[^\s@]+$`；**`name` 與 `email` 含 `\r` 或 `\n` 一律回 400**（防標頭注入）。失敗時回 400 `{"error":"invalid","field":"<第一個不合格的欄位>"}`。
3. 以 `TURNSTILE_SECRET` 呼叫 Turnstile `siteverify`；`success` 為 false 回 403。若 `ALLOWED_HOSTNAMES` 非空，另外檢查回應的 `hostname` 在清單內，否則回 403。本機 `.dev.vars` 把 `ALLOWED_HOSTNAMES` 設為空字串，因為測試 secret 回傳的 hostname 是假的。
4. 以 **Resend API**（`fetch` 呼叫 REST，不需 MIME 函式庫）寄信：
   - `from`：`Unizza 官網 <noreply@send.unizzagames.com>`（寄件子網域，見第 4 節 DNS）
   - `to`：`CONTACT_TO` 環境變數（`gazzaliu@unizzagames.com`）
   - `reply_to`：填表人 Email
   - `subject`：`官網詢問：{name}`
   - 內文：**純文字（`text`）**，不送 HTML，因此不需跳脫。
5. Resend 回 2xx → 回 200；否則回 502。
6. `DRY_RUN=1` 時改為 `console.log` 信件內容並回 200 —— **但請求的 host 是 `unizzagames.com` 或 `www.unizzagames.com` 時一律忽略 `DRY_RUN`**，確保正式環境不會吞掉詢問。

Secrets（`wrangler secret put`，不進 repo）：`TURNSTILE_SECRET`、`RESEND_API_KEY`。一般變數：`CONTACT_TO`。

**為何不用 Cloudflare Email Routing 的 `send_email`：** 它需要啟用 Email Routing，而 Email Routing 會接管網域 MX 記錄；`unizzagames.com` 的 MX 目前指向 Google Workspace，啟用後既有信箱會停止收信。Resend 只在寄件子網域加 SPF/DKIM，不動主網域 MX。

### 4. 網域與 DNS

1. 把 `unizzagames.com` 的 nameserver 從 Namecheap 改到 Cloudflare（免費方案）。**改之前**：
   - 在 Namecheap 檢查 DNSSEC；若已啟用，先關閉（移除 DS 記錄）並等 DS 記錄 TTL 過期，否則換 nameserver 後整個網域（含收信）會驗證失敗。搬完後可在 Cloudflare 重新啟用 DNSSEC。
   - 在 Cloudflare 匯入 DNS 記錄後，逐筆核對 Google Workspace 的 MX、SPF（`TXT v=spf1 ...`）、DKIM（`google._domainkey`）、DMARC、以及 Google 驗證 TXT 都存在，否則收信會中斷。
   - 刪除匯入進來的 apex 與 `www` 的 A / AAAA / CNAME 記錄（例如 Namecheap 停放頁或舊的 Webflow 記錄），確認沒有其他服務使用後再刪；否則 Worker Custom Domain 會因記錄衝突建立失敗。郵件相關記錄不動。
   改完後寄一封測試信到 `info@unizzagames.com` 確認仍收得到。
2. Resend：新增網域 `send.unizzagames.com`，把 Resend 給的 SPF / DKIM 記錄加到 Cloudflare DNS，等待驗證通過。
3. Turnstile：在 Cloudflare dashboard 建立 widget，hostname 允許清單為 `unizzagames.com`、`www.unizzagames.com`。
4. **正式網址為 `https://www.unizzagames.com`**。apex（`unizzagames.com`）以 Cloudflare **Redirect Rule** 301 轉到 `www`（保留路徑與查詢字串），不經過 Worker。apex 仍綁定為 Worker Custom Domain，讓它有 proxied 的 DNS 記錄，Redirect Rule 才會生效。

### 5. 部署

- Workers Builds 連接 GitHub `GazzaLiu/Unizza-Website`：push 到 `main` 自動部署。預覽網址關閉（見第 1 節），變更在合併前以本機 `wrangler dev` 驗證。
- `_headers`：`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`，以及**上線初期的 `X-Robots-Tag: noindex`**。移除時機：第 7 節內容清單全部打勾的同一個 commit。

### 6. 本機測試

- `.dev.vars`：`TURNSTILE_SECRET=1x0000000000000000000000000000000AA`（Cloudflare 公開的「永遠通過」測試 secret）、`ALLOWED_HOSTNAMES=`（空字串，跳過 hostname 檢查）。前端在 localhost 自動使用測試 sitekey（見第 3 節）。測「永遠失敗」路徑改用 `2x0000000000000000000000000000000AA`。
- `RESEND_API_KEY` 本機可用真 key 寄到自己信箱，或在 `.dev.vars` 設 `DRY_RUN=1`，讓 Worker 印出信件內容而不呼叫 Resend（localhost 不在正式 host 清單，DRY_RUN 生效）。
- `npx wrangler dev` 後用 curl 驗證：
  - `GET /api/contact` → 405
  - `POST /api/nope` → 404
  - `POST /api/contact` 空 body → 400
  - `name` 含 `\n` → 400
  - `turnstileToken: "XXXX.DUMMY.TOKEN.XXXX"`，`.dev.vars` 用「永遠失敗」secret → 403
  - 正確資料 + `turnstileToken: "XXXX.DUMMY.TOKEN.XXXX"`，用「永遠通過」secret → 200，信件到達（或 DRY_RUN 印出內容）
- 瀏覽器（localhost）：以 DevTools 封鎖 `challenges.cloudflare.com` 後重新整理聯絡頁 → 10 秒內出現 mailto 後備訊息。

### R3-1 — consistency

**Problem**

> Section 3 frontend has two rules that conflict. One keeps the submit button disabled until the Turnstile callback supplies a token, and disables it again on expiry. The other says any non-200 response calls turnstile.reset() and re-enables the button. After reset() the previous token is spent and no new token exists until the callback fires again. Re-enabling the button immediately lets the user resubmit with the spent or empty token, which returns 403 'verification failed'. That is the same misleading failure R2-5 was meant to prevent.

**Remedy**

> On any non-200: clear the stored token, call turnstile.reset(), and keep the button disabled until the callback delivers a new token. Only the callback re-enables the button.

### R3-2 — completeness

**Problem**

> The frontend handles callback and expired-callback but not Turnstile failures: error-callback, api.js failing to load (an ad or privacy blocker, a network block on challenges.cloudflare.com), or a challenge that never completes. The submit button starts disabled and only the callback enables it, so in these cases the form is dead with no explanation. The mailto fallback appears only on a 5xx or network error from /api/contact. A prospective client would be left unable to make contact.

**Remedy**

> Add an error-callback, plus a load or timeout check for api.js. When either triggers, show a message with the mailto:info@unizzagames.com fallback, for example by revealing .w-form-fail. Add this case to the local test plan.

### R3-3 — clarity

**Problem**

> The Section 6 curl cases '錯誤的 Turnstile token → 403' and '正確資料 → 200' do not say which turnstileToken value to send. Cloudflare's test secrets are designed to accept the dummy token that the test sitekey produces (XXXX.DUMMY.TOKEN.XXXX). An arbitrary or empty string may not give the documented result, so the 200 case may not reproduce from curl.

**Remedy**

> Specify the token for each curl case, for example turnstileToken "XXXX.DUMMY.TOKEN.XXXX" with the always-pass secret for 200 and with the always-fail secret for 403. Alternatively, say to take the token from the browser flow on localhost.
